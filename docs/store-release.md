## 未解決の記録保存問題

利用者から、同じSafariタブで端末内のレビューが空になったとの報告あり。原因は未特定。v214で直接の公開申請にも端末保存を加え、v215でSQLエクスポートのJSON貼り付け復元を追加した。既存の「たまごっち」は復元済み。これらの対処を、消失原因の特定として扱わない。

## 今回の準備（v218・v219）

- サポートメールを公開。受信・返信は利用者からテスト完了の報告あり。
- 公開Web版のデータ取扱いに合わせたプライバシーポリシーを公開し、その他・レビュー・サポートからリンク。
- 投稿別の通報メール作成、送信済みデータの削除相談を追加。これはApple向けアプリ内アカウント削除機能の完了ではない。
- [データ取扱い一覧](data-inventory.md)を作成。事業者側のログ保存・本番認証設定は未照合。

## 表示修正（v220）

- 片付け写真の初回案内をBefore／Afterの両列の上へ配置し、案内キャラを40pxに固定。写真用の横幅100%指定が案内キャラに及ぶ問題を修正。
- 備蓄不足・未登録時のトリケラさんを、破損のない元の画像データへ復元。v219への文字列置換が画像のbase64内の偶然一致にも及んでいた。
- 埋め込みイラスト19件のハッシュ検証をリリースチェックへ追加。今後のバージョン更新は画像データを置換対象から除く。
- 利用者からプライバシーポリシーと投稿別の通報メール作成のOKを受領。

## 投稿管理の実装（v221）

- 投稿ルールと申請時の同意を追加。
- 投稿者ブロック／一括解除、本人の送信済み投稿一覧・削除、本人のアカウントと関連投稿・写真・投票の削除を実装。
- 新しい管理機能はサーバーの `stock_review_controls()` が2を返す場合に有効化。未適用時の既存閲覧・投稿は維持。
- 本番には `supabase/migrations/002_review_controls.sql` の適用が必要。管理者向け `review-server-setup.html` でコピーして適用できる。本番適用と実データでの削除テストは未実施。
- 独立したPostgreSQLで匿名アクセス拒否・本人/他人の分離・セッション確認・関連データの連動削除をテスト。認証スキーマはテスト用の最小構成であり、本番設定の一致確認は別途必要。
- アカウント削除は、削除者本人が操作する。確認のために既存の所有者アカウントをこちらで削除しない。
- プロバイダー側のGoogleアカウントは削除しない。Appleログインは未導入。ネイティブ認証と審査要件の最終照合は継続する。

## 再現手順

Node.js 22以上。iOS実ビルドには対応するmacOS・Xcode、Androidには対応するJDK・SDKを用意する。

```sh
npm ci --ignore-scripts
npm run native:add:android
npm run native:add:ios
npm run native:verify
# 生成済みプロジェクトへのWeb版更新
npm run native:sync
```

`native-web/`・`ios/`・`android/`は生成物としてgit対象外。生成後の調整は再現可能な設定やスクリプトに記録する。

アプリID `jp.minimalisttako.totonoebousai` は仮設定。Web版とストア版は保存領域が異なるため、端末間での引き継ぎにはバックアップの読み込みを使う。

鍵・パスワード・証明書を公開リポジトリやチャット本文に置かない。
